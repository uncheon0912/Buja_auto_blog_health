# 정보성 블로그 제목·자료 수집 에이전트

이 스킬은 별도 API 키 없이 Codex가 제공하는 웹 검색과 로컬 파일 기능만 사용한다. 외부 유료 검색 API, OpenAI API 호출, 자동 발행은 사용하지 않는다.

## 입력 처리

1. 사용자가 제공한 제목의 개수를 센다.
2. 번호, 순서, 공백을 제외한 제목 원문을 그대로 보존한다. 명시적인 승인 없이 제목을 교정하거나 키워드를 추가하지 않는다.
3. 동일하거나 지나치게 유사한 제목도 삭제하거나 병합하지 않는다. 해당 제목 아래에 `중복·유사 가능성`과 비교 대상 번호만 표시한다.
4. 한 제목이 여러 분야에 걸치면 독자의 핵심 질문을 해결하는 데 가장 직접적인 유형 하나를 주 분류로 정하고, 필요한 경우 보조 분류를 주의사항에 기록한다.
5. 각 제목은 서로 독립적으로 조사한다. 한 제목에서 찾은 근거를 다른 제목에 자동으로 전용하지 않는다.

## 주제 분류

다음 중 하나로 분류한다.

- 일반 생활정보
- 금융·보험 정보
- 법률·세무 정보
- 병원·건강·의료 정보
- 기타 전문정보

병원, 건강, 증상, 통증, 질환, 치료, 시술, 수술, 진단, 약, 의약품, 회복, 재활 또는 이에 준하는 의미가 있으면 의료 안전 모드를 적용한다. 교통사고처럼 법률·보험과 의료가 함께 있는 제목도 의료 내용이 포함되면 의료 안전 모드를 함께 적용한다.

## 실행 흐름

각 제목에 대해 다음 순서를 지킨다.

1. 상태를 `입력 완료`로 기록한다.
2. 주제 유형, 의료 안전 모드 여부, 독자가 가장 궁금해할 핵심 질문 한 문장을 정리하고 상태를 `주제 분석`으로 바꾼다.
3. 답변에 필요한 사실을 다음처럼 구분한다.
   - 정의와 적용 범위
   - 현재 법령·제도·공식 지침
   - 조건에 따라 달라지는 예외
   - 독자가 취할 수 있는 안전한 다음 행동
   - 최신 확인이 필요한 수치·기준·기간
4. 최신성 또는 전문성이 필요한 주장은 웹에서 확인한다. 검색 및 출처 선택에는 [자료 조사 정책](references/2026-08-27-research-source-policy.md)을 적용한다.
5. 의료 안전 모드라면 조사 전에 [의료 안전 정책](references/2026-08-27-medical-safety-policy.md)을 읽고 적용한다.
6. 근거가 확인된 주장과 확인되지 않은 내용을 분리하고 상태를 `자료 확인`으로 바꾼다.
7. 사용자가 원고 작성을 요청한 경우에만 상태를 `원고 작성`으로 진행한다. 의료 원고는 표현 검수 후에도 자동 발행하지 않는다.
8. 결과는 [출력 스키마](references/2026-08-27-output-schema.md)에 맞춰 제목별로 독립 작성한다.

## 출처 사용 원칙

- 검색 결과의 제목이나 요약문만 근거로 사용하지 말고 원문 페이지를 연다.
- 기관명, 문서명, URL, 게시일 또는 개정일, 확인일을 가능한 범위에서 기록한다.
- 출처가 실제 주장과 직접 연결되는지 확인한다.
- 수치, 통계, 기간, 치료 효과, 사례를 만들거나 일반화하지 않는다.
- 공식 자료끼리 충돌하면 차이를 숨기지 말고 적용 시점과 범위를 확인한다.
- 근거가 부족하면 `현재 확인된 자료만으로 단정하기 어렵다`고 명시한다.
- 광고성 블로그, 병원 홍보글, 출처 불명 게시물은 핵심 근거로 사용하지 않는다.

## 상태 관리

허용 상태는 다음과 같다.

- 입력 완료
- 주제 분석
- 자료 확인
- 원고 작성
- 의료·표현 검수
- 네이버 입력
- 임시저장 완료
- 실패 또는 사용자 확인 필요

상태를 건너뛰지 말고 제목별로 따로 기록한다. 조사만 요청받은 경우 정상 종료 상태는 `자료 확인`이다. 원고 작성, 네이버 입력 또는 임시저장은 사용자가 해당 작업을 명시적으로 요청한 경우에만 진행한다.

의료 관련 최종 원고의 최고 상태는 `임시저장 완료`이다. 발행, 예약 발행, 공개 전환 버튼은 누르지 않는다. 로그인, 보안 인증, 의료 판단, 출처 충돌 또는 사용자 선택이 필요하면 `실패 또는 사용자 확인 필요`로 두고 이유를 기록한다.

## 결과 저장과 이력

- 사용자가 결과 파일 저장을 요청했거나 프로젝트 작업 맥락에서 파일 산출이 필요한 경우에만 프로젝트 내부에 새 파일로 저장한다.
- 일반 결과 파일명은 `YYYY-MM-DD-번호-설명적이름.md` 형식을 사용한다.
- 동일 이름이 있으면 덮어쓰지 말고 `-02`, `-03`처럼 새 번호를 붙인다.
- 사용자 결정 사항과 작업 결과는 프로젝트 내부 `History` 폴더에 새 기록으로 남긴다.
- 기존 파일을 삭제, 덮어쓰기, 이름 변경하지 않는다.
- 현재 프로젝트 폴더 밖에는 파일을 만들거나 수정하지 않는다.

## 최종 점검

응답 전에 다음을 확인한다.

- 제목 수, 순서, 원문이 입력과 일치하는가?
- 유사 제목을 삭제하지 않고 표시했는가?
- 모든 제목에 분류, 의료 안전 모드, 핵심 질문, 필요 자료, 확인 자료, 미확인 내용, 작성 주의사항, 현재 상태가 있는가?
- 모든 핵심 주장에 직접 연결되는 출처가 있는가?
- 미확인 수치나 효과를 사실처럼 쓰지 않았는가?
- 의료 관련 자료가 최신 공식 자료인지 실행 시점에 다시 확인했는가?
- 의료 원고가 발행되지 않고 임시저장 단계에서 멈추는가?
