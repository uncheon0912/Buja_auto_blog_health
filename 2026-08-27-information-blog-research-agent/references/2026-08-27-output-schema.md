# 제목별 출력 스키마

## 배치 요약

결과 맨 앞에 다음 항목을 표시한다.

- 입력 제목 수
- 결과 제목 수
- 원문·순서 보존 점검: 통과 또는 실패
- 중복·유사 가능성이 있는 제목 번호
- 의료 안전 모드 적용 제목 번호
- 조사 기준일: `YYYY-MM-DD` (Asia/Seoul)

## 제목별 필수 출력

입력 순서대로 아래 형식을 반복한다. 제목을 별도 글로 작성할 수 있도록 각 제목의 자료를 독립적으로 완결한다.

```markdown
## 제목 01

- 제목 번호: 01
- 원본 제목: 사용자가 입력한 제목 원문
- 현재 상태: 자료 확인
- 주제 분류: 병원·건강·의료 정보
- 의료 안전 모드 적용 여부: 예
- 중복·유사 가능성: 없음 또는 비교 대상 번호와 이유
- 독자의 핵심 질문: 한 문장

### 필요한 자료

- 확인 항목과 필요한 문서 종류

### 확인된 자료와 출처

| 근거 ID | 확인된 사실 | 기관 | 문서명 | 게시·개정일 | 확인일 | 원문 URL | 적용 범위·주의점 |
|---|---|---|---|---|---|---|---|
| T01-S01 | ... | ... | ... | ... | ... | ... | ... |

### 확인하지 못한 내용

- 확인하지 못한 항목과 그 이유
- 필요한 경우: 현재 확인된 자료만으로 단정하기 어렵다.

### 작성 시 주의사항

- 단정 금지, 적용 조건, 독자가 확인할 사항
```

## 상태 기록 규칙

각 제목에는 현재 상태를 하나만 기록한다. 작업 이력에는 상태 변경 시각과 이유를 남길 수 있다.

- 입력만 검증됨: `입력 완료`
- 분류와 핵심 질문까지 작성됨: `주제 분석`
- 필요한 근거와 미확인 사항까지 구분됨: `자료 확인`
- 사용자가 요청한 원고가 작성됨: `원고 작성`
- 의료 또는 표현 검수가 완료됨: `의료·표현 검수`
- 사용자의 명시적 요청으로 네이버 편집기에 입력됨: `네이버 입력`
- 사용자의 명시적 요청으로 임시저장됨: `임시저장 완료`
- 진행할 수 없거나 사용자 선택이 필요함: `실패 또는 사용자 확인 필요`

## 원문 보존 데이터

검증이 필요한 경우 결과와 함께 다음 구조의 JSON 장부를 새 파일로 저장한다. `original_title`은 사용자의 제목 문자열과 문자 단위로 같아야 한다.

```json
{
  "research_date": "2026-08-27",
  "titles": [
    {
      "number": 1,
      "original_title": "자동차보험 치료비는 누가 부담할까요?",
      "category": "금융·보험 정보",
      "medical_safety_mode": true,
      "core_question": "사고 치료비를 어떤 주체와 보험이 어떤 조건에서 부담하는가?",
      "required_materials": ["현재 자동차보험 보상 기준"],
      "verified_sources": [],
      "unverified_items": ["구체적인 사고 조건이 없어 적용 범위 확인 필요"],
      "writing_cautions": ["개별 사고의 과실과 약관에 따라 달라질 수 있음을 표시"],
      "similar_to": [],
      "status": "자료 확인"
    }
  ]
}
```

검증용 JSON은 내부 장부이며, 실제 조사 결과에는 빈 `verified_sources`를 허용하지 않는다. 자료를 확인하지 못했다면 상태를 `실패 또는 사용자 확인 필요`로 바꾸고 이유를 `unverified_items`에 기록한다.

## 파일 저장 규칙

- 제목별 조사 보고서: `YYYY-MM-DD-번호-설명적이름.md`
- 배치 검증 장부: `YYYY-MM-DD-research-ledger.json`
- 실행 이력: `History/YYYY-MM-DD-research-history.md`
- 같은 파일명이 이미 있으면 덮어쓰지 않고 설명적 이름 뒤에 순번을 추가한다.
