# 오류·중단·재개 정책

## 기본 원칙

- 같은 동작을 무한 반복하지 않는다.
- 안전하고 결과가 명확한 동작만 최대 한 번 재시도한다.
- 성공 여부가 불분명한 동작은 재시도하지 않는다.
- 현재 글이 불완전하면 다음 글로 넘어가지 않는다.
- 실패한 글을 완료 또는 임시저장 성공으로 표시하지 않는다.
- 발행, 예약, 공개 설정으로 우회하지 않는다.

## 재시도 가능 여부

| 상황 | 자동 재시도 | 처리 |
|---|---|---|
| 텍스트 범위 선택이 해제됐고 내용 변화가 없음 | 최대 1회 | 대상을 다시 선택하고 서식 적용 |
| 형광펜 또는 볼드가 적용되지 않았음이 명확함 | 최대 1회 | 같은 지정 서식만 다시 적용 |
| 인용구 선택이 실패했으며 본문 변화가 없음 | 최대 1회 | 같은 인용구를 다시 선택 |
| 표 삽입 전 메뉴가 닫혔고 문서 변화가 없음 | 최대 1회 | 같은 표 구조로 다시 시도 |
| 임시저장 버튼 클릭 후 성공 여부 불명확 | 금지 | 중복 저장 방지를 위해 중단 |
| 저장 완료 표시가 사라져 확인 불가 | 금지 | 사용자 확인 필요 |
| 화면 전환 중 예기치 않은 기존 원고 발견 | 금지 | 덮어쓰지 않고 중단 |
| 로그인·2차 인증·캡차 | 금지 | 사용자가 직접 처리할 때까지 대기 |
| 지정 색상이나 인용구를 식별할 수 없음 | 금지 | 다른 서식을 임의 선택하지 않음 |
| 발행 관련 화면이 예기치 않게 나타남 | 금지 | 설정을 바꾸지 않고 중단 |

재시도 전에는 현재 문서가 변하지 않았는지 확인한다. 재시도 횟수를 History에 기록한다.

## 오류 기록

오류가 발생하면 새 History 파일에 다음을 기록한다.

- 발생 시각: Asia/Seoul
- 진행 번호와 전체 개수
- 제목
- 실패 단계
- 화면에서 확인한 현상
- 성공 여부
- 재시도 가능 여부
- 재시도 횟수
- 다음 진행 차단 여부
- 사용자에게 필요한 행동

민감한 화면의 전체 내용, 로그인 정보, 인증 코드, 쿠키, 세션 값은 기록하지 않는다.

## 로그인·인증·캡차

1. 브라우저 동작을 즉시 중단한다.
2. 사용자에게 직접 로그인 또는 인증이 필요하다고 알린다.
3. 아이디, 비밀번호, 인증 코드 입력을 요청하거나 대신 처리하지 않는다.
4. 사용자가 직접 처리하는 동안 기다린다.
5. 사용자가 완료했다고 알린 뒤 재개 승인을 별도로 기다린다.
6. 재개 전 현재 편집기와 저장 상태를 다시 확인한다.

인증 과정에서 페이지가 바뀌어 현재 원고 상태가 불확실하면 재입력하거나 다음 글로 넘어가지 않는다.

## 임시저장 불확실성

다음 중 하나면 상태를 `사용자 확인 필요`로 둔다.

- 임시저장 버튼을 눌렀지만 성공 메시지가 없음
- 저장 시각이나 상태가 갱신됐는지 알 수 없음
- 현재 제목과 임시저장 항목의 연결을 확인할 수 없음
- 네트워크 오류가 저장 직후 발생함
- 페이지 이동으로 저장 결과를 확인할 수 없음

이 상태에서는 임시저장을 다시 누르지 않고 다음 글로 넘어가지 않는다. 사용자가 네이버에서 직접 상태를 확인한 뒤 재개 여부를 결정한다.

## 중단 기준

다음 상황에서는 전체 자동화를 중단한다.

- 현재 글의 저장 성공 여부가 불확실함
- 로그인 또는 인증이 필요함
- 캡차가 나타남
- 기존 원고를 덮어쓸 위험이 있음
- 발행 관련 화면에서 안전하게 빠져나왔는지 확인할 수 없음
- 지정 서식을 실제로 확인할 수 없음
- 검수 완료 원고와 현재 파일의 SHA-256이 다름
- 사용자 입력으로 브라우저 상태가 바뀜
- 한 번의 안전한 재시도 후에도 오류가 반복됨

## 재개 절차

사용자가 다시 시작하도록 승인한 경우 다음 순서로 재개한다.

1. 실행 명세와 프로젝트 내부 History 체크포인트를 다시 읽는다.
2. 마지막으로 성공이 확정된 번호와 제목을 확인한다.
3. 불확실한 제목이 있으면 사용자에게 네이버에서 직접 확인하도록 요청한다.
4. 완료된 제목을 건너뛰되 재입력하지 않는다.
5. 재개할 번호가 마지막 성공 번호의 다음 번호인지 확인한다.
6. 로그인 상태와 빈 새 글쓰기 화면을 확인한다.
7. 자동화 시작 전 PC 사용 중단 안내를 다시 한다.
8. 사용자가 재개를 승인한 뒤 진행한다.

중단 중 경과한 시간을 글 사이 60초 대기로 자동 인정하지 않는다. 재개 시 필요한 대기 여부를 현재 상태와 마지막 성공 체크포인트를 기준으로 다시 판단한다.

## 완료 상태

제목별 상태는 다음 중 하나를 사용한다.

- 입력 전
- 입력 중
- 서식 검수 중
- 임시저장 확인 중
- 임시저장 완료
- 실패
- 사용자 확인 필요
- 인증 대기

`임시저장 완료`는 화면에서 성공 근거를 확인하고 History 체크포인트를 만든 경우에만 사용한다.
