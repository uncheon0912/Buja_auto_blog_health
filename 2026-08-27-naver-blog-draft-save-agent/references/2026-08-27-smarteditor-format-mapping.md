# 스마트에디터 서식 변환 규칙

이 문서는 표시 문법이 적용된 검수 완료 원고를 네이버 스마트에디터의 실제 서식으로 변환할 때 사용한다. 실행 시점의 보이는 UI와 접근 가능한 상태를 기준으로 조작하며 오래된 좌표나 고정된 화면 배치를 가정하지 않는다.

## 공통 원칙

- 원고 텍스트와 문단 순서를 바꾸지 않는다.
- 태그를 먼저 모두 지운 뒤 서식을 추정하지 않는다. 태그별 대상 범위를 확인하면서 실제 서식을 적용하고 해당 태그만 제거한다.
- 각 변환 뒤 텍스트 누락, 중복, 줄바꿈 변화를 확인한다.
- 원하는 서식이나 색상을 명확히 찾지 못하면 비슷해 보이는 다른 옵션을 선택하지 않는다.
- 발행, 예약, 공개 설정과 관련된 UI는 열거나 변경하지 않는다.

## 표시 문법 대응표

| 원고 표시 | 스마트에디터 결과 | 변환 후 확인 |
|---|---|---|
| `[NAVER_TITLE]...[/NAVER_TITLE]` | 상단 제목 입력란 | 태그 없음, 원본 제목 문자 일치 |
| `[DIVIDER]` | 제목 아래 가로 구분선 | 본문 시작 전에 구분선 존재 |
| 고정 안내문 | 일반 본문 | 원문·문장부호·대괄호 일치 |
| `[TITLE_BOX_LIGHT_GREEN_CENTER]...[/TITLE_BOX_LIGHT_GREEN_CENTER]` | 1행 1열 표 | 연한 녹색, 중앙 정렬, 원본 제목 일치 |
| `[QUOTE_HEADING]...[/QUOTE_HEADING]` | 왼쪽 세로선 인용구 | 모든 주요 소제목에 같은 스타일 |
| `[HIGHLIGHT_YELLOW]...[/HIGHLIGHT_YELLOW]` | 노란색 형광펜 | 지정 문장만 노란색 |
| `[HIGHLIGHT_GREEN]...[/HIGHLIGHT_GREEN]` | 연두색 형광펜 | 지정 문장만 연두색 |
| `[HIGHLIGHT_PINK]...[/HIGHLIGHT_PINK]` | 분홍색 형광펜 | 지정 문장만 분홍색 |
| Markdown `**...**` | 실제 볼드 | 별표 없음, 대상만 굵게 |
| Markdown 정보표 | 스마트에디터 표 | 2열 이하, 헤더 포함 전체 5행 이하 |
| `[FAQ_BOX]자주 묻는 질문[/FAQ_BOX]` | 박스형 인용구 | 일반 소제목과 구분되는 스타일 |
| `[FINAL_SUMMARY]...[/FINAL_SUMMARY]` | 일반 최종 정리 본문 | 태그 없음, 본문 순서 유지 |

## 상단 제목

1. `[NAVER_TITLE]` 안의 문자열을 원본 제목과 문자 단위로 비교한다.
2. 네이버 제목 입력란에 원본 제목만 입력한다.
3. 표시 태그나 번호를 입력하지 않는다.
4. 입력 뒤 화면에 보이는 제목을 다시 읽어 원문과 비교한다.

자동 완성, 맞춤법 교정 또는 브라우저 확장 기능이 제목을 바꾼 흔적이 있으면 진행하지 않는다.

## 구분선과 고정 안내문

- 구분선은 제목 다음, 고정 안내문 이전에 하나만 삽입한다.
- 고정 안내문은 원고에 있는 문자열을 그대로 사용한다.
- 줄바꿈을 제외한 띄어쓰기, 대괄호, 문장부호를 바꾸지 않는다.
- 안내문을 이유로 이후 의료 검수나 서식 확인을 생략하지 않는다.

## 제목 박스

1. 네이버 표 기능으로 1행 1열 표를 만든다.
2. 원본 제목을 셀에 입력한다.
3. 셀 안 텍스트를 중앙 정렬한다.
4. 지정된 연한 녹색 계열 배경을 적용한다.
5. 화면에서 1행 1열, 중앙 정렬, 연한 녹색, 제목 원문을 확인한다.

제목 박스를 Markdown 본문 정보표와 합치지 않는다. 배경색 선택지가 명확하지 않거나 적용 여부를 볼 수 없으면 임의의 색을 고르지 않는다.

## 본문과 문단

- 원고 순서대로 한 문단씩 입력한다.
- 문단 사이 빈 줄을 유지한다.
- 편집기 자동 서식으로 문단이 합쳐지거나 분리되지 않았는지 확인한다.
- 원고에 없는 홍보 문구, 해시태그, 링크 또는 CTA를 추가하지 않는다.

## 볼드

1. `**` 쌍 안의 정확한 텍스트 범위를 식별한다.
2. 별표를 제외한 텍스트만 입력한다.
3. 해당 범위에 실제 볼드를 적용한다.
4. 볼드 종료 지점을 확인한다.
5. 다음 답변이나 문단이 일반 굵기로 시작하는지 확인한다.

Q&A 질문은 `Q.`부터 질문 끝까지 굵게 표시한다. 질문 뒤 답변이 굵어져 있으면 임시저장 전 수정한다.

## 인용구

- 모든 `[QUOTE_HEADING]` 블록에 동일한 왼쪽 세로선 스타일을 사용한다.
- 태그 밖의 본문까지 인용구에 포함하지 않는다.
- 소제목 텍스트의 앞뒤 공백과 줄바꿈이 변하지 않았는지 확인한다.
- FAQ는 `[FAQ_BOX]` 대상에 박스형 인용구를 사용해 일반 소제목과 구분한다.

대상 스타일을 식별할 수 없으면 다른 인용구를 임의로 사용하지 않고 실패로 기록한다.

## 형광펜

1. 색상 태그와 닫는 태그 사이의 문장 범위를 식별한다.
2. 태그를 제외한 문장만 입력한다.
3. 정확한 문장 범위를 선택한다.
4. 지정된 형광펜 색상을 적용한다.
5. 선택이 해제된 뒤 화면에서 색상을 확인한다.
6. 다음 문단까지 형광펜이 이어지지 않는지 확인한다.

태그 이름과 실제 색상 대응은 바꾸지 않는다. 지정 색상을 찾지 못하면 실패로 기록한다.

## 본문 정보표

Markdown 표마다 다음을 확인한다.

- 열: 최대 2개
- 헤더: 1행
- 데이터: 최대 4행
- 전체: 최대 5행
- 빈 셀: 없음
- 병합: 없음

구분 행 `|---|---|`은 셀 내용으로 입력하지 않는다. 제목 박스는 본문 정보표 개수나 행 수에 포함하지 않는다.

표 변환 뒤 각 셀의 텍스트, 열 수, 행 수를 원고와 비교한다. 긴 셀이 있더라도 브라우저 입력 단계에서 임의로 축약하지 않는다.

## 잔여 표시 검사

임시저장 전에 본문 전체에서 다음 표시가 화면에 남아 있지 않은지 확인한다.

- `[NAVER_TITLE]`
- `[DIVIDER]`
- `[TITLE_BOX_LIGHT_GREEN_CENTER]`
- `[QUOTE_HEADING]`
- `[HIGHLIGHT_YELLOW]`
- `[HIGHLIGHT_GREEN]`
- `[HIGHLIGHT_PINK]`
- `[FAQ_BOX]`
- `[FINAL_SUMMARY]`
- Markdown 볼드 별표 `**`
- Markdown 표 구분 행 `---`

태그가 남았거나 텍스트가 누락됐다면 임시저장을 성공 처리하지 않는다.
