# 네이버 임시저장 실행 절차

## 1. 실행 명세 점검

브라우저 연결 전에 제목별 실행 명세를 확인한다.

- 진행 번호가 1부터 연속되는가
- 전체 개수가 모든 항목에서 같은가
- 원본 제목과 `[NAVER_TITLE]`이 같은가
- 제목 박스도 같은 원본 제목인가
- 검수 상태가 `통과` 또는 `자동 수정 후 통과`인가
- 검수 시 기록한 SHA-256과 현재 원고 파일이 같은가
- 파일이 현재 프로젝트 안에 있는가
- 이미 완료된 제목과 재개 번호가 충돌하지 않는가

사전검사기가 한 항목이라도 실패하면 브라우저를 열지 않는다.

## 2. 사용자 준비 확인

첫 브라우저 동작 직전에 다음 의미로 안내하고 확인을 기다린다.

> 네이버 스마트에디터 자동 입력을 시작합니다. 자동화가 진행되는 동안 마우스와 키보드 사용을 잠시 멈춰 주세요. 로그인, 2차 인증 또는 캡차가 나타나면 바로 알려드리고 기다리겠습니다.

사용자 확인 없이 시작하지 않는다.

## 3. 브라우저와 로그인 상태

- 네이버 URL에 적합한 브라우저를 선택한다.
- 사용자가 브라우저를 지정했다면 해당 브라우저만 사용한다.
- 실행 시점의 보이는 UI 상태를 읽는다.
- 비밀번호 저장소, 쿠키, 로컬 저장소, 프로필 파일을 검사하지 않는다.

로그인 화면, 2차 인증 또는 캡차가 나타나면 사용자에게 직접 처리하도록 요청하고 기다린다. 사용자가 완료와 재개를 승인한 뒤 상태를 다시 확인한다.

## 4. 새 글쓰기 화면

1. 네이버 블로그의 새 글쓰기 화면을 연다.
2. 빈 새 문서인지 확인한다.
3. 기존 제목, 본문 또는 임시저장 복구 문구가 있으면 덮어쓰지 않는다.
4. 기존 내용이 있으면 현재 제목과 단계를 알리고 중단한다.

## 5. 원고 입력

[스마트에디터 서식 변환 규칙](2026-08-27-smarteditor-format-mapping.md)을 적용한다.

1. 상단 제목
2. 구분선
3. 고정 안내문
4. 연한 녹색 중앙 정렬 제목 박스
5. 본문 문단
6. 볼드
7. 왼쪽 세로선 인용구 소제목
8. 형광펜
9. 본문 정보표
10. FAQ 박스형 인용구
11. Q&A 질문 볼드
12. 최종 정리

각 단계 뒤 필요한 최소 확인을 수행하되 발행 관련 UI는 열지 않는다.

## 6. 임시저장 전 점검

다음을 화면에서 확인한다.

- 상단 제목 원문
- 구분선
- 고정 안내문
- 제목 박스의 1행 1열, 제목 원문, 중앙 정렬, 연한 녹색
- 주요 소제목의 동일한 왼쪽 세로선 인용구
- 지정된 형광펜 색상과 범위
- 2열 이하, 전체 5행 이하의 본문 정보표
- 별표와 표시 태그 제거
- FAQ 박스형 인용구
- Q&A 질문 전체 볼드와 답변 일반 굵기
- 발행되지 않은 편집 상태

확인할 수 없는 항목이 있으면 임시저장을 성공 처리하지 않는다.

## 7. 임시저장

1. 화면에서 명확하게 식별되는 임시저장 기능만 사용한다.
2. 발행 버튼과 발행 설정 화면은 사용하지 않는다.
3. 임시저장 동작 뒤 완료 메시지, 시각, 상태 또는 임시저장 항목을 확인한다.
4. 클릭이 수행됐다는 사실만으로 성공 처리하지 않는다.
5. 성공 여부가 불분명하면 다시 클릭하지 않고 중단한다.

## 8. 저장 후 검수

- 제목이 원문과 같은가
- 고정 안내문과 제목 박스가 있는가
- 인용구와 형광펜이 실제 적용됐는가
- 정보표가 제한 안에 있는가
- Q&A 질문이 볼드인가
- 임시저장 상태가 화면에 확인되는가
- 공개 또는 발행 상태가 아닌가

발행 여부를 확인하기 위해 발행 설정 화면을 열지 않는다. 현재 편집기와 임시저장 표시에서 확인 가능한 범위만 사용한다.

## 9. History 체크포인트

성공을 확인한 뒤 프로젝트 내부에 새 History 파일을 만든다.

권장 파일명:

`History/YYYY-MM-DD-번호-draft-save-history.md`

기록 내용:

- Asia/Seoul 저장 시각
- 현재 번호와 전체 개수
- 원본 제목
- 검수 상태
- 입력 원고 SHA-256
- 성공을 확인한 화면 근거
- 재시도 횟수
- 다음 제목
- 현재 상태: `임시저장 완료`

로그인 정보, 인증 코드, 쿠키, 세션 값, 원고 속 개인정보를 기록하지 않는다.

## 10. 다음 글 전 대기

다음 제목이 있으면 다음 문구를 표시한다.

```text
✅ {현재번호}/{전체개수} 임시저장 완료
⏳ 네이버 블로그의 안정적인 처리를 위해 60초 대기합니다.
⏭️ 다음 제목: {다음 제목}
```

정확히 60초 동안 브라우저 동작을 하지 않는다. 대기 시간이 끝난 다음에만 새 글쓰기 화면을 연다.

마지막 글은 대기하지 않고 완료 보고로 이동한다.

대기 횟수는 `전체 성공 글 수 - 1`이 아니라 원래 순서에서 실제로 다음 처리 대상이 남아 있는 성공 구간마다 한 번이다. 제목 10개를 중단 없이 완료하면 9회, 총 9분이다.

## 11. 완료 보고

- 전체 제목 수
- 임시저장 성공 수
- 실패 수
- 사용자 확인 필요 수
- 글별 제목과 처리 상태
- 실패 단계와 화면 근거
- 재시도 횟수
- 직접 확인이 필요한 항목
- 마지막 성공 번호
- 재개 가능한 다음 번호

완료 보고와 실행 요약도 새 History 파일로 기록한다. 기존 체크포인트를 수정하지 않는다.
