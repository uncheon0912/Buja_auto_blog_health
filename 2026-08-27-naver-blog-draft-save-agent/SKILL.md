# 네이버 정보성 블로그 임시저장 에이전트

이 스킬은 최종 검수를 통과한 정보성 블로그 원고를 입력 순서대로 네이버 블로그 스마트에디터에 옮기고 임시저장한다.

발행, 예약 발행, 공개 설정 변경은 이 스킬의 범위가 아니다. 모든 글은 임시저장까지만 처리한다.

## 절대 금지

- 발행 버튼을 클릭하지 않는다.
- 발행 설정 화면을 열기 위해 발행 버튼을 클릭하지 않는다.
- 예약 발행을 설정하지 않는다.
- 공개·비공개·이웃 공개 등 공개 설정을 변경하지 않는다.
- 검수를 통과하지 않은 글을 에디터에 입력하지 않는다.
- 임시저장 성공 여부가 불확실한 상태에서 다음 글로 넘어가지 않는다.
- 네이버 아이디, 비밀번호, 인증 코드, 쿠키 또는 세션 정보를 읽거나 기록하지 않는다.
- 기존 자동화 파일, 원고 파일 또는 History 파일을 덮어쓰지 않는다.
- 원고에 없는 내용을 브라우저 입력 중 임의로 추가하거나 수정하지 않는다.

임시저장 버튼이나 임시저장 성공 상태를 명확하게 식별할 수 없으면 발행 관련 버튼을 대신 사용하지 말고 중단한다.

## 연결할 프로젝트 스킬

입력 전에 다음 검수 스킬의 결과를 확인한다.

- `../2026-08-27-medical-naver-content-review-agent/SKILL.md`
- `../2026-08-27-medical-naver-content-review-agent/references/2026-08-27-review-output-format.md`

실제 서식 변환에는 다음 콘텐츠 규칙을 사용한다.

- `../2026-08-27-naver-information-blog-content-agent/SKILL.md`
- `../2026-08-27-naver-information-blog-content-agent/references/2026-08-27-naver-draft-format.md`

기존 스킬 파일은 수정하지 않는다.

## 입력 조건

각 제목에 대해 다음 정보가 필요하다.

- 진행 번호
- 전체 제목 수
- 원본 제목
- 최종 원고
- 원고 파일 경로 또는 전체 본문
- 최종 검수 상태
- 검수한 원고와 입력할 원고가 같음을 확인할 수 있는 정보
- 의료 관련 원고 여부

허용 검수 상태는 다음 두 가지뿐이다.

- `통과`
- `자동 수정 후 통과`

다른 상태의 원고는 입력하지 않는다.

- 사용자 확인 필요
- 근거 부족
- 의료 표현 재작성 필요
- 네이버 서식 오류

`자동 수정 후 통과`인 원고는 검수에 반영된 최종 수정본만 입력한다. 수정 전 원고와 구분할 수 없으면 중단한다.

## 사전 점검

브라우저를 조작하기 전에 다음을 확인한다.

1. 제목 목록과 원고 목록의 개수가 같은가
2. 제목 순서와 진행 번호가 연속적인가
3. 모든 제목이 원고의 `[NAVER_TITLE]`과 문자 단위로 같은가
4. 상단 제목과 제목 박스의 원문이 같은가
5. 검수 상태가 입력 가능한 상태인가
6. 검수 이후 원고가 변경되지 않았는가
7. 이미 임시저장 완료된 제목이 있는가
8. 재개 작업이라면 완료된 제목 다음 번호가 정확한가

원고 해시 또는 검수 기록과 현재 원고가 다르면 입력하지 않고 재검수를 요청한다.

## 자동화 시작 안내

모든 사전 점검을 통과한 뒤 첫 브라우저 동작 직전에 사용자에게 다음 의미로 안내한다.

> 네이버 스마트에디터 자동 입력을 시작합니다. 자동화가 진행되는 동안 마우스와 키보드 사용을 잠시 멈춰 주세요. 로그인, 2차 인증 또는 캡차가 나타나면 바로 알려드리고 기다리겠습니다.

사용자가 준비됐다고 확인하기 전에는 브라우저 입력을 시작하지 않는다.

## 브라우저 선택과 보안

네이버 URL과 기존 로그인 상태에 적합한 브라우저를 선택한다. 브라우저를 직접 지정받은 경우 해당 브라우저만 사용한다.

- 브라우저의 보이는 화면과 접근 가능한 편집기 상태만 사용한다.
- 쿠키, 로컬 저장소, 브라우저 프로필, 비밀번호 저장소를 검사하지 않는다.
- 네이버 아이디와 비밀번호를 대신 입력하거나 요청하지 않는다.
- 로그인 화면, 2차 인증, 캡차가 나타나면 자동 진행을 중단한다.
- 사용자가 브라우저에서 직접 인증하도록 요청하고 완료될 때까지 기다린다.
- 인증 완료 후 사용자가 재개를 승인해야만 진행한다.

브라우저 UI는 실행 시점의 화면을 기준으로 확인하며 오래된 좌표나 고정 선택자에 의존하지 않는다.

## 글별 실행 순서

각 제목에 대해 [임시저장 실행 절차](references/2026-08-27-draft-save-runbook.md)를 읽고 다음 순서로 처리한다.

1. 대상 제목의 검수 상태를 다시 확인한다.
2. 새 글쓰기 화면인지 확인한다.
3. 기존 작성 내용이 있다면 덮어쓰지 않고 중단한다.
4. 네이버 제목 영역에 원본 제목을 그대로 입력한다.
5. 제목 아래에 구분선을 삽입한다.
6. 사용자 지정 고정 의료 정보 안내문을 그대로 입력한다.
7. 1행 1열 제목 박스를 삽입한다.
8. 제목 박스에 원본 제목을 그대로 입력한다.
9. 제목 박스에 연한 녹색 배경을 적용한다.
10. 제목 박스 문장을 중앙 정렬한다.
11. 본문을 원고 순서대로 입력한다.
12. `**텍스트**` 표시를 제거하고 해당 텍스트에 실제 볼드를 적용한다.
13. `[QUOTE_HEADING]` 표시를 제거하고 왼쪽 세로선 인용구를 적용한다.
14. 형광펜 태그를 제거하고 지정된 실제 형광펜 색상을 적용한다.
15. Markdown 정보표를 네이버 표 기능으로 변환한다.
16. FAQ 문구를 일반 소제목과 구분되는 박스형 인용구로 적용한다.
17. 모든 Q&A 질문 전체에 볼드를 적용한다.
18. 표시용 태그와 별표 기호가 본문에 남아 있지 않은지 확인한다.
19. 전체 서식을 화면에서 다시 검사한다.
20. 임시저장 기능만 사용한다.
21. 임시저장 성공 여부를 화면에서 확인한다.
22. 성공한 경우에만 새 History 체크포인트를 기록한다.

## 제목 박스

제목 박스는 본문 정보표와 별도로 처리한다.

- 1행 1열
- 원본 제목 그대로
- 중앙 정렬
- 연한 녹색 배경
- 빈 셀 없음
- 불필요한 병합 없음

연한 녹색과 중앙 정렬을 실제 화면에서 확인할 수 없으면 임의로 다른 색상이나 정렬을 적용하지 않고 실패로 기록한다.

## 본문 정보표

Markdown 표를 스마트에디터의 실제 표로 변환한다.

- 최대 2열
- 헤더 1행
- 데이터 최대 4행
- 전체 최대 5행
- 빈 셀 없음
- 불필요한 병합 없음
- 제목 박스와 별도 객체

원고의 표 구조가 이 제한을 넘으면 브라우저에서 임의로 축약하지 않고 입력을 중단한다.

## 인용구

- 모든 주요 소제목에 동일한 왼쪽 세로선 인용구 스타일을 적용한다.
- `[QUOTE_HEADING]` 시작·종료 태그는 실제 본문에서 제거한다.
- `자주 묻는 질문`은 일반 소제목과 다른 박스형 인용구를 적용한다.
- 인용구 적용 뒤 텍스트 누락과 줄바꿈 변화를 확인한다.

원하는 인용구 스타일을 화면에서 식별하지 못하면 임의의 다른 스타일을 선택하지 않는다.

## 형광펜 변환

다음처럼 변환한다.

- `[HIGHLIGHT_YELLOW]문장[/HIGHLIGHT_YELLOW]` → 노란색
- `[HIGHLIGHT_GREEN]문장[/HIGHLIGHT_GREEN]` → 연두색
- `[HIGHLIGHT_PINK]문장[/HIGHLIGHT_PINK]` → 분홍색

변환 뒤 모든 형광펜 태그를 제거한다.

지정 색상이 없거나 적용 여부를 확인할 수 없으면 다른 색상을 대신 적용하지 않는다. 해당 단계 실패로 기록하고 안전한 경우에만 한 번 재시도한다.

단정적이거나 과장된 의료 문장이 강조돼 있음을 발견하면 서식을 적용하지 않고 검수 단계로 돌려보낸다.

## 볼드 변환

- `**텍스트**`의 별표를 제거하고 해당 텍스트만 실제 볼드 처리한다.
- Q&A 질문은 `Q.`부터 질문 끝까지 전체 볼드 처리한다.
- 답변은 일반 굵기로 시작하는지 확인한다.
- 볼드 해제 지점을 확인해 이후 문단까지 굵어지지 않도록 한다.
- 별표 기호가 본문에 남지 않았는지 확인한다.

볼드 범위가 불분명하거나 답변까지 굵어진 경우 저장 전에 수정한다. 안전하게 수정할 수 없으면 임시저장 성공 상태로 처리하지 않는다.

## 임시저장 전 화면 검수

임시저장 직전에 다음을 화면에서 확인한다.

- 제목이 원문과 같은가
- 구분선이 있는가
- 고정 안내문이 있는가
- 1행 1열 제목 박스가 있는가
- 제목 박스가 중앙 정렬·연한 녹색인가
- 인용구 소제목이 정상 적용됐는가
- 표시용 태그가 남아 있지 않은가
- 형광펜 색상이 원고 지정과 같은가
- 정보표가 2열 이하인가
- Q&A 질문이 전체 볼드인가
- Q&A 답변은 일반 굵기인가

하나라도 확인할 수 없으면 저장 성공 단계로 진행하지 않는다.

## 임시저장과 성공 확인

발행 버튼을 사용하지 않고 화면에서 명확하게 식별되는 임시저장 기능만 사용한다.

성공은 다음과 같은 화면 근거 중 하나 이상으로 확인한다.

- 임시저장 완료 메시지
- 임시저장 시각 또는 상태 표시
- 현재 제목과 연결된 임시저장 항목
- 브라우저 화면에서 확인 가능한 동등한 성공 표시

저장 버튼을 클릭했다는 사실만으로 성공으로 판단하지 않는다.

성공 여부를 확인할 수 없으면 다음 글로 넘어가지 않는다. 저장 상태가 불명확한 상황에서는 중복 저장을 피하기 위해 임시저장을 다시 누르지 않고 사용자 확인을 요청한다.

## History 체크포인트

임시저장 성공이 확인된 글마다 프로젝트 내부 `History`에 새 파일을 생성한다.

기록 항목:

- 저장 시각: Asia/Seoul
- 진행 번호와 전체 개수
- 원본 제목
- 검수 상태
- 임시저장 성공 근거
- 현재 처리 상태
- 다음 제목
- 재시도 횟수
- 사용자 확인 필요 여부

네이버 아이디, 비밀번호, 인증 코드, 쿠키, 세션 정보, 원고 속 개인정보는 기록하지 않는다.

기존 History 파일을 수정하지 않는다. 같은 이름이 있으면 새 순번을 붙인다.

## 글 사이 60초 대기

마지막 글이 아니라면 임시저장 성공과 History 기록 후 사용자에게 다음 형식으로 표시한다.

```text
✅ {현재번호}/{전체개수} 임시저장 완료
⏳ 네이버 블로그의 안정적인 처리를 위해 60초 대기합니다.
⏭️ 다음 제목: {다음 제목}
```

그다음 정확히 60초 동안 기다린다.

- 브라우저 클릭 금지
- 입력 금지
- 새 글 화면 열기 금지
- 새 탭 열기 금지
- 새로고침 금지
- 다른 브라우저 동작 금지

사용 중인 브라우저 제어 기능의 대기 메커니즘으로 60초를 측정한다. 대기 중 오류나 사용자 입력이 발생하면 타이머를 임의로 이어서 처리하지 않고 상태를 확인한다.

60초가 모두 지난 뒤에만 새 글쓰기 화면을 연다.

마지막 제목의 임시저장이 완료되면 60초를 기다리지 않고 종료한다. 제목이 10개라면 대기는 정확히 9회, 총 9분이다.

## 오류와 재시도

[오류·재개 정책](references/2026-08-27-error-resume-policy.md)을 적용한다.

- 오류가 발생한 제목과 단계, 화면에서 확인한 원인을 기록한다.
- 같은 동작을 무한 반복하지 않는다.
- 안전하고 결과가 명확한 동작만 최대 한 번 재시도한다.
- 임시저장 성공 여부가 불확실하면 다시 저장하지 않는다.
- 재시도 후에도 실패하면 `사용자 확인 필요`로 남긴다.
- 현재 글이 불완전한 상태이면 다음 글로 넘어가지 않는다.
- 다음 글 진행이 안전하지 않으면 전체 자동화를 중단한다.
- 실패한 글을 발행하거나 완료 상태로 표시하지 않는다.

## 로그인·인증·캡차

로그인 만료, 2차 인증 또는 캡차가 나타나면 즉시 중단한다.

사용자에게 현재 중단 단계와 직접 처리해야 할 화면을 안내한다. 사용자가 완료했다고 알리고 재개를 승인할 때까지 기다린다.

재개 시 다음을 다시 확인한다.

1. 로그인 상태
2. 현재 에디터와 임시저장 상태
3. 마지막 성공 체크포인트
4. 완료된 제목
5. 재개할 다음 제목

완료된 제목을 다시 입력하지 않는다. 임시저장 성공이 불확실한 제목은 사용자 확인 없이 건너뛰거나 재입력하지 않는다.

## 완료 보고

작업이 끝나거나 중단되면 다음을 보고한다.

- 전체 제목 수
- 임시저장 성공 수
- 실패 수
- 사용자 확인 필요 수
- 각 제목과 처리 상태
- 실패 단계와 원인
- 재시도 횟수
- 네이버에서 직접 확인할 항목
- 마지막 성공 번호
- 재개 가능한 다음 번호

실행 결과는 프로젝트 내부 `History`에 새 파일로 기록한다.

## 네이버 입력 허용 조건

다음 조건을 모두 충족한 원고만 네이버에 입력할 수 있다.

- 검수 결과가 `통과` 또는 `자동 수정 후 통과`
- 입력 원고가 실제 검수된 최종본과 동일함
- 제목 원문과 순서가 일치함
- 사용자가 자동화 시작 직전 PC 사용 중단 안내를 확인함
- 로그인·인증·캡차 차단이 없음
- 이전 글의 임시저장 성공 여부가 확실함

하나라도 충족하지 못하면 브라우저 입력을 시작하거나 계속하지 않는다.
