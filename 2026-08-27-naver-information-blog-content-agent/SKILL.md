# 네이버 정보성 블로그 콘텐츠 생성 에이전트

이 스킬은 제목마다 서로 독립된 네이버 정보성 블로그 원고를 작성한다. 제목이 10개이면 원고도 10개 작성하며, 한 원고의 표현이나 근거를 다른 제목에 자동으로 재사용하지 않는다.

모든 원고는 네이버 블로그 임시저장을 전제로 한다. 별도 API 키나 유료 검색 API를 사용하지 않으며, 의료 관련 원고는 발행·예약 발행·공개 전환을 수행하지 않는다.

## 기존 자료수집 스킬 연결

원고를 작성하기 전에 제목별 근거를 확인한다.

프로젝트에 다음 스킬이 있으면 해당 규칙과 조사 결과를 우선 활용한다.

`../2026-08-27-information-blog-research-agent/SKILL.md`

조사 결과가 없거나 최신성이 필요한 내용은 작성 시점에 공식 웹 자료를 다시 확인한다. 의료·법률·보험·제도 관련 내용은 검색 결과 요약이나 광고성 블로그가 아니라 직접 확인한 공식 원문을 근거로 사용한다.

확인되지 않은 수치, 사례, 통계, 진단, 치료 효과, 치료 기간을 만들지 않는다. 충분한 근거가 없으면 해당 내용을 빼거나 `현재 확인된 자료만으로 단정하기 어렵다`고 표시한다.

## 제목 처리

1. 입력된 제목의 개수를 센다.
2. 제목의 순서와 원문을 문자 단위로 그대로 보존한다.
3. 제목을 축약, 교정, 과장하거나 키워드를 추가하지 않는다.
4. 같은 제목이나 유사한 제목도 삭제하거나 병합하지 않는다.
5. 각 제목에 원고 하나를 배정한다.
6. 네이버 블로그 제목과 본문 상단 제목 박스에 동일한 원문을 사용한다.
7. 두 위치의 제목이 한 글자라도 다르면 저장이나 네이버 입력을 중단한다.

## 원고 분량

- 글당 약 1,200~1,500자를 기본으로 한다.
- 표시 태그를 제외한 실제 독자용 텍스트를 기준으로 분량을 확인한다.
- 정보량이 부족하면 짧아질 수 있으며, 같은 내용을 반복해 분량을 채우지 않는다.
- 분량보다 근거의 정확성과 자연스러운 흐름을 우선한다.
- 원고를 미리 보여줄 때 예상 글자 수를 함께 안내한다.

## 고정 의료 정보 안내문

모든 원고에서 네이버 블로그 제목 아래 구분선 다음에 아래 문장을 그대로 입력한다.

본 게시글은 보건복지부 가이드 라인에 따라 의료법 제57조 제3항 각 호의 사전심의를 받지 아니할 수 있는 항목만으로 이루어진 [일반적인 건강상식, 의학정보를 제공하는 정보 공유 목적]으로 작성되었습니다.

띄어쓰기, 대괄호, 문장부호를 포함해 임의로 수정하지 않는다.

이 문구가 있다는 이유만으로 본문 전체가 의료법 또는 의료광고 검수에서 면제된다고 판단하지 않는다. 실제 의료 관련 표현은 [의료 콘텐츠 안전 규칙](references/2026-08-27-medical-content-safety.md)에 따라 별도로 검수한다.

## 필수 본문 순서

각 원고는 다음 순서를 정확히 따른다.

1. 네이버 블로그 제목
2. 구분선
3. 고정 의료 정보 안내문
4. 원래 제목을 그대로 반복한 연한 녹색 1칸 제목 박스
5. 도입 본문
6. 핵심 문장 형광펜
7. 인용구 형태의 첫 번째 소제목
8. 설명 본문
9. 핵심 문장 형광펜
10. 2열 정보표
11. 인용구 형태의 두 번째 소제목
12. 설명 본문
13. 인용구 형태의 세 번째 소제목
14. 설명 본문
15. `자주 묻는 질문` 인용구 박스
16. Q&A
17. 최종 정리

구체적인 표시 문법과 출력 템플릿은 원고 작성 전에 [네이버 원고 형식](references/2026-08-27-naver-draft-format.md)을 읽고 적용한다.

## 도입부

- 독자가 실제로 겪을 수 있는 구체적인 상황으로 시작한다.
- 제목에서 제기한 질문의 핵심 답을 앞부분에서 먼저 안내한다.
- 필요한 경우 도입부의 핵심 질문만 볼드 처리한다.
- 한 문단은 2~4문장으로 짧게 작성한다.
- 문단 사이에 빈 줄을 둔다.
- 과도한 인사말, 광고 문구, 병원 또는 기관 홍보 문구를 넣지 않는다.
- 확인되지 않은 진단이나 결과를 단정하지 않는다.

## 인용구 소제목

- 주요 소제목 세 개를 모두 `[QUOTE_HEADING]` 문법으로 표시한다.
- 왼쪽 세로선이 있는 네이버 인용구 스타일을 전제로 한다.
- 이모지와 불필요한 번호를 붙이지 않는다.
- 질문형 또는 결론형 한 줄 문장을 우선한다.
- 제목과 직접 관련된 내용만 사용한다.
- 각 소제목 아래에는 2~3개의 짧은 문단을 작성한다.

표시 문법:

`[QUOTE_HEADING]운동할 때 왜 허리가 반복해서 아플까요?[/QUOTE_HEADING]`

## 형광펜

- 핵심 문장 1~2문장만 강조한다.
- 문단 전체를 강조하지 않는다.
- 근거가 부족하거나 단정적인 문장을 강조하지 않는다.
- 기본 색상은 노란색이다.
- 도입부에는 분홍색, 설명 부분에는 연두색을 선택적으로 사용할 수 있다.
- 한 원고에서 최대 세 가지 색상만 사용한다.
- 볼드와 형광펜을 불필요하게 중복하지 않는다.

허용 문법:

`[HIGHLIGHT_YELLOW]핵심 문장[/HIGHLIGHT_YELLOW]`

`[HIGHLIGHT_GREEN]핵심 문장[/HIGHLIGHT_GREEN]`

`[HIGHLIGHT_PINK]핵심 문장[/HIGHLIGHT_PINK]`

## 볼드

- 도입부의 핵심 질문이나 중요한 용어에만 선별적으로 사용한다.
- 문단 전체를 습관적으로 볼드 처리하지 않는다.
- 모든 Q&A 질문은 질문 전체를 볼드 처리한다.
- Q&A 답변은 일반 글씨로 작성한다.
- 네이버 입력을 수행한 경우 실제 볼드 적용 여부를 다시 확인한다.

## 정보표

모든 원고에는 정보표를 최소 한 개 포함한다.

- 가로 2열만 사용한다.
- 첫 번째 행을 헤더로 사용한다.
- 헤더 아래 내용은 최대 4행이다.
- 긴 문장 대신 비교하거나 확인할 핵심 기준을 짧게 정리한다.
- 제목 박스는 정보표 개수에 포함하지 않는다.
- 제목과 직접 관련 없는 항목으로 행을 채우지 않는다.

## Q&A

- 글 마지막 부분에 `[FAQ_BOX]자주 묻는 질문[/FAQ_BOX]`을 넣는다.
- 질문은 2~3개 작성한다.
- 각 질문 전체를 Markdown 볼드로 표시한다.
- 답변은 짧고 직접적으로 작성한다.
- 본문에서 다루지 않은 새로운 주장을 추가하지 않는다.
- 의료 글에서는 진단, 치료 효과, 치료 기간을 단정하지 않는다.

## 문체

- 결론과 핵심 답변을 앞에 배치한다.
- 단호하지만 차분하고 따뜻한 존댓말을 사용한다.
- 전문용어는 처음 등장할 때 쉬운 말로 설명한다.
- 보고서처럼 딱딱한 나열을 피한다.
- 상투적인 중요성 강조를 반복하지 않는다.
- 독자의 불안을 과도하게 자극하지 않는다.
- 근거와 해석을 구분한다.
- 치료나 효과를 약속하지 않는다.
- 마지막에는 독자가 직접 확인하거나 기록할 수 있는 구체적인 행동을 안내한다.
- 병원 방문이나 상담을 과도하게 유도하는 광고성 문구를 넣지 않는다.

## 원고 작성과 승인 절차

1. 제목별 조사 자료와 확인되지 않은 내용을 검토한다.
2. 제목마다 독립된 원고를 작성한다.
3. 지정된 표시 문법과 필수 순서를 적용한다.
4. 제목 원문, 고정 안내문, 분량, 표, Q&A, 강조 표현을 검사한다.
5. 의료 관련 글은 별도의 의료·표현 검수를 수행한다.
6. 완성된 원고 전체를 사용자에게 먼저 보여준다.
7. 제목별 예상 글자 수와 검수 결과를 함께 표시한다.
8. 콘텐츠 파일을 만들지 않은 상태로 사용자 승인을 기다린다.
9. 사용자가 승인한 제목의 원고만 프로젝트 내부에 새 파일로 저장한다.
10. 거절되거나 수정 요청을 받은 원고는 저장하지 않고 채팅에서 수정안을 다시 보여준다.

여러 원고가 있을 때 사용자는 전체 승인 또는 제목별 승인을 할 수 있다. 승인되지 않은 원고를 다른 원고와 함께 일괄 저장하지 않는다.

## 콘텐츠 파일 저장

사용자 승인 후에만 프로젝트 내부 `Contents` 폴더에 새 파일을 만든다.

파일명은 `YYYY-MM-DD-번호-설명적이름.md` 형식을 사용한다. 파일명에 사용할 수 없는 문자는 제거할 수 있지만, 파일 안의 네이버 제목과 제목 박스 원문은 변경하지 않는다.

같은 이름이 이미 있으면 덮어쓰지 않고 `-02`, `-03`처럼 새 순번을 붙인다.

기존 콘텐츠 파일, 스킬 파일 또는 이력 파일을 삭제·덮어쓰기·이름 변경하지 않는다. 현재 프로젝트 밖에는 파일을 만들거나 수정하지 않는다.

저장 결과와 사용자 승인 범위는 프로젝트 내부 `History` 폴더에 새 기록으로 남긴다.

## 네이버 입력과 임시저장

콘텐츠 파일 저장 승인은 네이버 입력 승인으로 간주하지 않는다.

사용자가 별도로 네이버 입력을 요청한 경우에만 승인된 원고를 편집기에 입력한다. 입력 후 다음 항목을 확인한다.

- 상단 제목과 제목 박스의 원문 일치
- 구분선과 고정 안내문
- 연한 녹색 제목 박스와 중앙 정렬
- 인용구 소제목 세 개
- 형광펜 색상과 적용 범위
- 볼드 적용 범위
- 2열 정보표
- 자주 묻는 질문 박스
- 문단 간격과 모바일 가독성

의료 관련 원고는 반드시 임시저장까지만 처리한다. 발행, 예약 발행, 공개 전환 버튼은 누르지 않는다.

## 최종 검수

사용자에게 원고를 보여주기 전에 제목별로 확인한다.

- 입력 제목 수와 원고 수가 같은가?
- 제목 순서와 원문을 유지했는가?
- 상단 제목과 제목 박스가 문자 단위로 같은가?
- 고정 안내문이 정확히 한 번 들어갔는가?
- 필수 17단계 순서를 지켰는가?
- 도입부에서 핵심 답을 먼저 안내했는가?
- 인용구 소제목이 세 개인가?
- 형광펜이 핵심 문장에만 사용됐는가?
- 표가 2열, 헤더 1행, 내용 최대 4행인가?
- Q&A가 2~3개이며 질문 전체가 볼드인가?
- 같은 내용을 반복해 분량을 늘리지 않았는가?
- 확인되지 않은 사례, 수치, 진단, 효과를 만들지 않았는가?
- 의료 표현을 별도로 검수했는가?
- 광고성 CTA가 없는가?
- 구체적인 안전 행동으로 마무리했는가?
- 아직 승인받지 않은 원고를 파일로 저장하지 않았는가?
